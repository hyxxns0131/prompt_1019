프롬포트의 세가지 유형

- 서술형: 상황과 배경(맥락)을 이야기하듯 설명
- 지침형: 지켜야 할 것을 1, 2, 3 규칙으로 나열
- 함수형: 입력 → 처리 → 출력 틀을 정해 두고 값만 바꿔 쓰기

(1) 서술형: 상황을 이야기하듯

AI가 상황을 이해하도록 역할, 배경, 목적을 문장으로 설명합니다. 대화하듯 편하게 쓰는 방식이에요

```jsx
<수업 예시>
당신은 10년 경력의 무역 전문가입니다.
중소기업 수출 담당자가 HS code를 처음 배우는 상황입니다.
이 사람에게 HS code의 개념과 중요성을 설명해 주세요
```

```jsx
<나의 예시>
당신은 10년 경력의 무역 전문가입니다.
중소기업 수출 담당자가 Incoterms에 대해 처음 배우는 상황입니다.
이 사람에게 Incoterms의 개념과 중요성, 각 Incoterms 간의 차이를 설명해 주세요.

```

(2) 지침형: 규칙을 번호로

꼭 지켜야 할 것을 단계별 규칙으로 나열합니다.

```jsx

2. 각 함수의 docstring 포함
3. 예외 처리는 반드시 포함
4. 결과는 json 형식으로 반환
```

```jsx
<수업 예시_무역 사무 프롬포트 규칙>
아래 규칙을 지켜서 바이어에게 보낼 납기 지연 안내 메일을 작성해 주세요.

2. 지연 이유는 한 문장으로
3. 새 납기일을 굵게 표시
4. 영어로 작성하고 5문장 이내로
```

왜 마크다운을 쓸까?

AI는 글을 한 덩어리로 읽지 않고 잘게 쪼개서(파싱) 이해합니다.

- 파싱: 글을 의미 단위로 쪼개는 것
- 마크다운: #, -, → 같은 기호로 제목ㆍ목록ㆍ강조를 표시하는 간단한 문서 작성법
- 기호로 구분해 주면 AI가 역할ㆍ조건ㆍ출력을 헷갈리지 않음 → 더 정확하고 일관된 답

> **서술형과 비교하면**
서술형도 나쁘지 않지만 두루뭉술하고 AI가 알아서 해석합니다.
마크다운은 체계적으로 관리 가능
> 

마크다운 핵심 기호 6가지

| **기호** | **이름** | **쓰임** |
| --- | --- | --- |
| # | 헤더(제목) | 프롬포트의 뼈대. # 큰 제목, ## 중간 제목, ### 소제목 |
| ‘’’ | 코드 블록 | 내가 넣는 자료를 지시문과 따로 묶기 |
| > | 인용문 | 절대 지켜야 할 조건 강조 |
| - | 목록 | 조건ㆍ제약을 나열(순서 상관없음) |
| | | 표 | 입력ㆍ출력 예시를 표로 |
| **글자** | 굵게 / 기울임 | 변수나 중요한 단어 강조(*글자*는 기울임) |

# 패턴과 프레임워크

## 왜 패턴을 하나씩 나눠서 배울까요?

| 이럴 때 | 오늘 배우는 패턴 |
| --- | --- |
| 주고받으며 진행해야 한다 | 게임 플레이 |
| 내 질문 자체가 애매하다 | 질문 개선 |
| 그럴듯하게 들린다 | 팩트 체크 |
| 긴 명령을 매번 반복한다 | 메타 언어 |
| 첫 답이 대충이다 | 리플렉션 |
| 긴 결과물이 엉성하다 | 아웃라인 확장 |
| 일반론만 늘어놓는다 | 컨텍스트 |
| 비슷한 걸 여러 개 만들어야 한다 | 무한 생성 |
| 매번 구성이 막막하다 | 프레임워크 |

```jsx
#게임
- 이름 : ()
- 목표 : (예: 10문제 중 많이 맞히기)
- 규칙 : (예: 4지선다, 한 문제에 15초)
- 점수 : (예: 정답 + 10점, 오답 0점)
- 끝 : (예: 10문제 후 점수와 "다시 하기" 버튼)
#화면
- 큰 글씨, 큰 버튼, 모바일에서도 잘 보이게
- 정답이면 초록색, 오답이면 빨간색으로 잠깐 표시
#제한
> HTMLㆍCSSㆍJavaScript 한 파일, 외부 라이브러리 금지
#출력
index.html 전체 코드 + 게임 방법 3줄
```

# 질문 개선 패턴

<1. 개선 후 답변>

```jsx
제 질문에 바로 답하지 말고, 먼저 제 질문을 분석해서 더 나은 질문으로 개선해 주세요.
개선된 질문을 보여준 뒤, 그 질문에 스스로 답하세요.
```

<2. 여러 버전 제시>

```jsx
제 질문을 3가지 다른 방향으로 개선해 주세요
각 버전이 어떤 목적에 맞는지 설명하고
제가 선택하면 그 버전으로 답하세요
```

<3. 문제 진단 먼저>

```jsx
제 질문의 문제점(모호함, 잘못된 전제, 누락된 맥락)을 먼저 지적하고
수정된 질문으로 답변하세요.
```

<질문개선 2. 다방향 분기형>


# APE 4단계

<APE 마스터 프롬포트>

```jsx
# 역할
당신은 프롬포트 엔지니어링 전문가입니다
주어진 작업에 대해 최적의 프롬포트를 자동으로 생성, 평가, 개선합니다.

## APE 실행 순서

### STEP 1: 후보 프롬포트 생성
아래 작업을 위한 프롬포트 후보 10개를 생성합니다
각 후보는 서로 다른 전략을 사용해야 합니다
전략 유형
- 역할 부여형: "당신은 xxx 전문가 입니다"
- 단계별 지시형: "step 1: ... step 2: ..."
- 예시 포함형: "다음과 같이 ~해주세요[예시]"
- 제약 명시형: "반드시 ~하되, ~하지 마세요"
- 목적 중심형: "최종 목표는 ~이며..."
- 독자 설정형: "~을 모르는 사람도 이해하도록"
- 형식 지정형: "결과를 [형식]으로 출력하세요"
- 품질 기준형: "~한 기준으로 평가했을 때 90점 이상..."
- 역방향형: "나쁜 예시는 ~이고, 좋은 예시는 ~"
- 메타 지시형: "이 작업의 본질은 ~이며 ..."

### STEP 2: 각 후보 자체 평가
각 프롬포트에 대해 아래 기준으로 점수 매기기:
명확성(0~25점): 지시가 모호하지 않은가
완전성(0~25점): 필요한 정보가 다 있는가
실행 가능성(0~25점): AI가 바로 실행하는가
품질 유도력(0~25점): 높은 품질의 결과를 이끌어 내는가
총 100점 만점

### STEP 3: 상위 3개 선택 후 교차 최적화
상위 3개 프롬포트의 강점을 결합하여 최종 최적 프롬포트 1개 생성

### STEP 4: 최적 프롬포트 출력
- 최적 프롬포트 전문
- 왜 이것이 최선인지 설명
- 사용 시 주의 사항

### 작업 입력
작업: {고객 클레임 이메일 답장 작성}
원하는 결과물: {고객이 화가 풀리고 우리 회사를 신뢰하게하는 답장}
피해야 할 것: {방어적 태도, 책임 회피, 형식적인 사과}
```
